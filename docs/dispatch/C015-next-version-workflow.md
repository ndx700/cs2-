## 1. 本轮做什么

完成用户选定的三课：D2-001 **中门挂门烟**、D2-010 **蓝车满烧火**、D2-014 **保持蹲姿跳投的中门炸烟 HE**。保留原编号，不能重新接入旧网页投法、空中开发站位或失败示范。
完整流程为：真实站位 → 第一人称瞄点 → 对应投法 → 道具跟随 → 右侧实时落点 → 动态效果。烟要看见扩散、成型、消散；火要看见地面起火、延迟蔓延、熄灭；HE 要看见局部炸烟缺口与回填。

C014 的“10月4日晚”目标已过去。本轮按下面的可核对成果推进，每次交接写下一项实际产物；不得沿用旧截止时间或承诺没有依据的完成时间。Ultra 和其余课程继续后排。

## 3. APP 工程师：现在就做

在自己的 `app/*` 分支保留 PR #10 成果与最新 main 的地图修复，先写 `docs/progress/APP-C015.md` 接单。不要覆盖资源、PM 文件或重新开发已有跟随/窗口。

1. **交出三维采集能力。** 增加仅开发可用的定位/导出方式：地图点选或射线拾取脚底、眼位、瞄点、落点；导出相机朝向、垂直 FOV、实际视口宽高、资源 SHA 和截图。区分轨道目标与真实相机眼位。若尚不能拾取地面，就先实现最小查询接入；列明接口和输入，不能只让资源方“提供全部坐标”。开发信息不进入普通教学界面。
2. **把三种投法表现正确。** 挂门烟是蹲下对齐后站起跳投；蓝车火是桶上抵墙并 W 跳投；HE 是保持蹲姿跳投。人物脚底由核对过的支撑面定位；跳跃期间可离地，待机和落地不得悬空。记录姿态/移动/出手阶段；既有接口不支持时，在 APP 契约中提出最小扩展并取得资源回执，不能三课共用一个不符参考的动作。
3. **先给资源方对照画面。** 用现有真实地图与资源方第一批定位值，提供同站位、同朝向的第三人称/第一人称画面；可在内部运行待测参数，但必须保持 DEVELOPMENT，记录来源和误差，不能宣称 CALIBRATED。没有手机时可先交完整地图的离屏图并注明运行环境；空背景 EGL 图不能作定位证据。
4. **修到效果实际可见。** 检查主画面和右窗的相机、深度、透明混合、裁剪及事件是否激活；连续演示烟/火/HE。跟随镜头和固定落点镜头避开墙体/地面遮挡，落地后稳定观察。两画面同钟、共用地图队列，暂停冻结、重播清空、跳到效果与后台/旋转恢复正常。
5. 接资源方逐课小包并跑真实解析器；回执逐字段报告接受/拒绝及原因。不能等三课全部完成后才做第一次联调。

第一项交付：**坐标采集/导出结果 + 中门挂门烟在真实地图中的站位与瞄点对照图**。附来源提交与实际测试。随后接 HE，再接蓝车火；蓝车资源准备可同步推进。

## 4. 资源工程师：现在就做

在自己的 `assets/*` 工作中接续最新检查点，先写 `docs/progress/RES-C015.md` 接单。沿用用户三视频及已有全层碰撞/材质查询资料，不重复索要已收到的原件。

1. **先定位静态教学场景。** 在完整地图中识别：挂门烟墙缝/墙边与墙面污点；蓝车火油桶支撑面、墙面和门锁上沿；HE 沙堆/蓝卡车车头角落与左门右下角。逐课输出脚底、眼位、瞄点、站/蹲姿与朝向候选，标明坐标来源、计算/图像拟合方法、误差和待核对项。
2. **用 3D 场景核对贴地与对点。** 先核对显示几何、已有 world_physics、层/形状语义以及 Source→显示变换。不能把未知命令点直接当脚底，不能把任意向下命中当正确站位。使用 APP 采集能力回传同视角图；关闭提示后仍应看见真实墙缝、污点、门锁或门角。局部不清楚时列出材质/UV和版本，精修需要的局部并走资源打包校验。
3. **逐课交轨迹与落点。** 第一批先交挂门烟的空间定位包和缺项表；随后交同场景 HE，再交蓝车火。节点注明数据来源与时间零点，反弹、落点/爆点和覆盖范围分别记录。图像推算的候选可以联调，未经核实不得写成游戏实测真值。
4. **补齐效果证据。** 对参考中能确认的阶段逐帧登记；缺完整消散/熄灭/回填的项目单列，不拿剪切前后拼成连续时间轴。没有游戏采集条件时，明确需要谁提供哪一段连续记录，其他空间定位和对照继续做；未证实的时序保持 pending。
5. **模型/碰撞缺失才升级修复。** 若现有完整显示模型与碰撞资料仍不能定位，交出具体缺失区域、表面和版本证据，补对应几何/碰撞。已有完整资料先复用，不以“重做全图物理”阻塞三处静态站位；动态门、官方烟火规则仍须单独验证。

第一项交付：**挂门烟真实地图三维定位记录 + 站位/瞄点证据 + APP 可核对的参数小包**。未知字段仍 null、importable=false；空间候选与已验证参数分开记录，不复制 DEV 数值。
