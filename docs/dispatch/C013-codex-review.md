3. 首批审查 APP [PR #5](https://github.com/ndx700/cs2-/pull/5) 和资源 [PR #4](https://github.com/ndx700/cs2-/pull/4)。先刷新 PR 状态、最新 head SHA、差异、进度、接口、评论和 CI；若已合并则核对对应 main 实现。
4. 检查当前两侧能否对接，分别列出代码缺陷、接口／资源缺项、待校准项和待手机验证项。需要修复的开发者据此更新各自 PR。

## 本轮重点

- 教学流程：站位、第一人称准星、投法、动作、轨迹、落点、第一／第三／上帝视角能否完整播放。
- 课程时钟：暂停是否冻结人物、轨迹和效果年龄；重播是否清理残留；视角切换、后台恢复和 GL 重建是否保持一致状态。
- 动态烟火／HE：烟的扩散成型消散、火的分区延迟蔓延、成型烟被 HE 局部冲开并回填。静态图或原型占位不能视为正式动态验收完成。
- 线程与资源：GL 线程边界、加载队列／内存上限、退出释放、多点触控、地图与资源版本、坐标单位和仅转换一次。
- 正式课程：稳定编号、真实来源、时间零点、未校准标记；待测值不得伪装成真实参数。
- 新增瞄点要求：按 C013 补充文件检查局部纹理一致性、手机可辨认性、可隐藏辅助提示和 CALIBRATED 证据。
- 范围：Ultra 仅为后续规划，本轮不启动职业 Demo 回放或服务器开发。

## 如何给两位工程师反馈

在被审查的 PR 留下具体问题：严重性、审查 head SHA、文件／函数、触发条件、实际影响、需求依据、建议修复和验证方式。只有进度说明而没有对应实现／数据时，明确缺少什么；已有正确实现不要重复要求重做。

首次完整人工任务审查记录保存到自己的 `docs/progress/CODEX-C013.md`，从最新 main 建 `codex/c013-review-<后缀>` 分支，通过 PR 交付。记录每个被审查 PR 的 head SHA、实际运行命令和结果、未运行原因、阻塞及证据。后续 PR head 改动后对受影响发现复查。

如分配了修复，使用独立 `codex/*` 分支和修复 PR；不要覆盖工程师正在使用的分支，不强推，不直接整合对方 PR。合并遵循用户授权与项目经理安排。当前入口文件的发布不代表 Codex 已接单，也不代表自动审查已开启。

## 验证与结论

按 AGENTS.md 执行资源恢复／校验、相关单元测试、编译和 Lint。明确区分本轮本地结果、CI 结果、历史桌面 EGL 记录和手机实测。构建通过不能证明实机瞄点或动态教学正确。

审查结论给出具体建议：可整合的部分、必须先修复的问题、仍需校准或手机验证的项。不把“未发现代码缺陷”写成“全部功能已验收”。

## 自动 PR 审查是单独设置

用户在已有授权的 Codex 会话里发送任务，可以启动一次审查；这与为仓库开启自动 PR 审查是不同的步骤。自动审查需要连接仓库并在 Codex 设置启用；已配置的仓库也可在 PR 用 `@codex review` 请求审查。不能把上传本文件当成设置成功。

官方依据：[GitHub PR review](https://learn.chatgpt.com/docs/third-party/github)。本仓库的根 AGENTS.md 已有 Code Review Rules，供 Codex 使用。
