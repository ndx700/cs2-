# CS2 Ultra 后续版本规划

日期：2026-10-04（北京时间）。状态：未来规划，尚未启动实现。
用户原文：[CS2 Ultra 未来展望原文](../sources/CS2_Ultra_未来展望原文.docx)，上传文件名为“cs2 urtra版本未来展望.docx”。
本文件记录用户方向及项目经理的后续拆分建议。当前 C013 教学 APK 继续优先交付，Ultra 不加入本轮验收，也不增加当前工程师的即时开发任务。

## 用户希望达到的体验

用户选择赛事、比赛、地图和回合，在可自由观察的三维战术沙盘里回放职业比赛。展示十名选手的位置、高度、朝向、视角、移动、蹲伏、跳跃、死亡，以及道具轨迹、烟火、击杀和炸弹事件。支持暂停、拖动时间、倍速和关键事件跳转，后续连接教学课程的职业使用案例。

人物可以先用轻量人形。必须体现跳箱的起跳、上升、落地和高度变化，避免瞬移、悬浮、穿墙、穿箱或脚陷入地面。地图坐标和地形对应的准确性优先于复杂人物动画。

## 当前低成本保留的基础

继续记录地图／资源版本和坐标体系：原点、轴向、单位、缩放、旋转和高度基准。保留稳定课程编号、明确时间零点、可替换数据接口与来源字段。

不为了 Ultra 立即重做现有播放框架、服务器或整张地图。碰撞与地形高度仍按当前任务的实际需要推进；已有自由相机或渲染地图不能视为已具备比赛回放能力。

## 后续技术验证建议

以下是项目经理建议的拆分顺序，具体排期与实现仍待研究。

| 阶段 | 验证目标 | 交付证据 |
| --- | --- | --- |
| 数据与坐标验证 | 合法获得一份 Dust2 Demo，识别地图版本并验证 CS2 到 APP 的坐标变换 | 原始数据来源、转换约定、地面及高处参照点误差记录 |
| 一回合人物回放 | 十名玩家的移动、视角、高度、蹲跳和死亡 | 时间对应的 CS2 参考与 APP 录屏；跳箱、蹲伏和落地检查 |
| 道具与事件 | 轨迹、弹跳、爆点、烟火、闪光相关状态、击杀和炸弹事件 | 按事件来源核对的时间线，明确缺失／推算字段 |
| 可交互回放 | 暂停、倍速、拖动、事件跳转和多视角 | 回退与跳转后人物、道具和事件状态一致的验证 |
| 服务与数据库 | 服务端解析，标准比赛数据下载，赛事／战队／选手检索 | 数据版本、解析兼容性与端侧加载／性能记录 |
| 远期分析 | 战术识别与 AI 解释，连接职业使用案例 | 标注事实与推断，建立可核对的分析结果 |

用户建议未来主要在服务器解析 Demo，APP 下载统一比赛数据；这是待验证架构方向，尚未选择解析器、数据服务或服务器方案。

## 先研究清楚的事项

- Demo 中哪些字段可直接读取，哪些动作只能推算，哪些数据缺失；不能将插值动作描述为实测事实。
- 地图版本差异、CS2 原始坐标到 APP 坐标的转换及高度贴合。误差容限需要用样本建立，不在本轮编造数值。
- 时间基准、采样间隔、插值及跳转时状态重建；回放位置以可信 Demo 数据为基础，不能由不准确的地图碰撞擅自改写。
- Demo 合法获取、版权及商业使用权限、服务稳定性和同步方式；第三方比赛信息网站仅作为可研究来源，不能默认可大规模抓取或商业使用。
- Android 性能：轻量人物、按需轨迹、移动端烟火、独立比赛数据加载和远处细节降低。
- 付费 Ultra 为用户的未来商业定位建议，尚未确定价格、上线日期或收益。

## 第一版 Ultra 验证目标

先完成一个 Dust2 回合的三维重放，核对十名玩家位置、朝向、高度、蹲跳、道具、击杀和时间轴。地图版本及坐标映射须可追溯。项目经理根据当前教学版本进度，后续决定何时开展技术验证；本文件不承诺现有 Demo 能完整提供全部目标数据。
